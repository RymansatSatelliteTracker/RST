# 要求内容

## 概要

- 固定のモード（Tx／Rx/衛星）にかかわらず、Tx周波数を無線機→RSTに逆同期(反映)することは一律不要とする。（Tx周波数のRST・無線機の同期は「RSTで計算した値を無線機へ送信」する一方向とする）
- 無線機（IC-9700）側でTXダイヤルを操作すると、無線機のトラッキング機能によりRXも自動で変化する。このRX変化はCI-Vトランシーブで通知されないため、トランシーブ待機の解除時にRX周波数を無線機から読み取り、RSTへ反映する。

## 実装状況

| 要求                                    | 状況                         |
| --------------------------------------- | ---------------------------- |
| 要求A: Tx周波数の無線機→RST反映の廃止   | 実装済み（テスト・doc更新済） |
| 要求B: トランシーブ待機解除時のRX読み取り | 設計済み・実機ログ確認待ち   |

## 背景

### 背景A: Tx逆同期の現状（要求Aの対象）

無線機ダイヤル操作に伴うTx/Rx周波数の「無線機→RST」反映は、改修前はモードごとに異なっていた（`TransceiverRecvFreqResolver.applyTxFromTransceiver`、`doc/30_画面設計/G2_メイン.md` 2.3.2節）。

| モード   | Tx側の無線機通知の取り込み（改修前）                           | Rx側の無線機通知の取り込み |
| -------- | -------------------------------------------------------------- | -------------------------- |
| 衛星固定 | 取り込む（基準周波数を再算出し、RST側の表示・基準周波数に反映） | 取り込む                   |
| 受信固定 | 取り込まない                                                   | 取り込む                   |
| 送信固定 | 取り込まない                                                   | 取り込む                   |

→ 改修により、衛星固定モードのTx側も取り込まない仕様に統一した。

### 背景B: TXダイヤル操作時のRX変化（要求Bの対象）

- IC-9700のサテライトモードでは、メインバンドがRX、サブバンドがTX。
- 無線機側のダイヤル操作は、メイン／サブのいずれかの選択バンドに対して行う。CI-Vのトランシーブは「選択中バンドの周波数」のみをRSTへ通知する。
- TXダイヤル操作時、無線機のトラッキングによりRXも自動変化するが、そのRX値はトランシーブでは通知されない。
- このため現状は、RXを直接ダイヤルしていなくても無線機側のRXが変化しているのに、RST側のRX表示・基準周波数に反映されない。
- 既存の送信一時停止機構: トランシーブ受信のたびに`startTransceiveWaitTimer`（周波数: `TRANSCEIVE_WAIT_MS` = 2000ms）で無線機への送信を停止し、タイマーは受信のたびに再設定される。

## 要求仕様

### 要求A: Tx周波数の無線機→RST反映の廃止（実装済み）

1. **全モード共通**で、無線機から通知されたTx周波数はRST側の`txFrequency`・Tx基準周波数（`txBaseFreq`）に反映しない。
2. Tx周波数の同期は「RSTが算出した値を無線機へ送信する」一方向のみとする（RST→無線機の既存送信処理は変更なし）。
3. Rx側の無線機通知の取り込み・基準周波数再算出ロジックは変更しない。
4. 無線機からのTx周波数変更通知（IPC `uplinkHz` 通知）自体は受信するが、RST側の状態への反映は行わない。

### 要求B: トランシーブ待機解除時のRX読み取り（新規）

1. **契機**: サテライトモードで、無線機からのTx（サブバンド）周波数のトランシーブ受信により送信一時停止（`isWaitSendFreq`）になった後、その待機が解除されるタイミング。
   - ダイヤル操作中は待機タイマーが延長され続けるため、読み取りは操作停止後（最後のトランシーブから`TRANSCEIVE_WAIT_MS`経過後）に1回だけ行われる。
2. **読み取り**: 待機解除時に、無線機からRX（メインバンド）の現在周波数を読み取る。
3. **反映**: 読み取ったRX周波数を、無線機からのRX通知（`downlinkHz`）と同様にRST側へ反映する（RX表示の更新、AutoOn時は基準周波数の再算出）。既存のRX反映処理（`TransceiverRecvFreqResolver.applyRxFromTransceiver`）を再利用する。
4. **送信再開の順序**: RXの読み取り・RST側への反映が完了するまで、RSTから無線機への周波数送信を再開しない。RSTの古いRX値で、ユーザーがダイヤル操作した結果を上書きしてはならない。
5. **対象条件**: 最後のトランシーブがTX（サブバンド）だった場合のみ読み取る。RXのトランシーブだった場合は、RX値は通知済みのため読み取らない。サテライトモードOFF時は対象外。
6. **RX/TX（Normal/Reverse）の区別**: 無線機のトラッキング設定（Normal/Reverse）は本件に関係しないため考慮しない。実機の値を正としてRXを読み取るのみとする。

## スコープ外（Non-Goals）

- 無線機への問い合わせ／IPC受信イベント購読自体の廃止・変更（要求A）。
- Normal／Reverseトラッキングの判別、およびTX変化量からRXを計算する方式。
- 運用モード（OpeMode）の同期ロジックの変更。
- ダイヤル操作中のリアルタイムなRX更新（反映は操作停止後とする）。

## 設計での決定事項（`2_design.md` 要求B参照）

- 読み取り方式: 新規コマンドは追加せず、既存の定期ループによる読み取り（バンド切り替え＋周波数取得）を使う。メインプロセスには、サブバンド（Tx）のトランシーブ受信時にRX読み取りを予約する仕掛け（`setRecvTxFreqHz` が `isRecvRxFreqUpdate` を立てる）が既にあり、待機解除後の最初のループで実行される。
- 送信再開の順序: 「RX読み取り待ち」の間は、RSTからの周波数要求（Tx・Rx）を無線機へ送らず破棄する。読み取り完了（待機解除後の最初のメインループ終了）で解除する。
- 対象機種: `TransceiverIcomController` を使うサテライトモード対応のICOM機種すべて（IC-9700専用の分岐は作らない）。
- 読み取り結果の受け渡し: 既存の周波数コールバック（`downlinkHz`）とレンダラ側の `applyRxFromTransceiver` を再利用する。レンダラ側の変更はなし。
- 実装前の確認: 反映されない原因は「RST側の古い要求値による上書き」と推定している（コード上の推論）。実機ログで確認してから実装する。

## 受け入れ基準

### 要求A

- 衛星固定・受信固定・送信固定の全モードにおいて、無線機側でTx周波数が変化しても、RST側の`txFrequency`・Tx基準周波数は変化しないこと。
- 上記いずれのモードでも、RST側で算出したTx周波数は従来通り無線機へ送信されること。
- Rx周波数に関する既存の同期挙動に変化がないこと。

### 要求B

- サテライトモードでTXダイヤルを操作し、操作を止めて待機時間が経過した後、無線機側で連動して変化したRX周波数がRST側のRX表示に反映されること。
- AutoOn時は、上記RXの変化に基づきRST側の基準周波数が再算出されること。
- RXの反映が完了する前に、RSTの古いRX値が無線機へ送信されないこと（ユーザーのダイヤル操作結果が上書きされないこと）。
- ダイヤル操作中（トランシーブが連続している間）は、RX読み取りが行われないこと。
- 最後のトランシーブがRXだった場合、およびサテライトモードOFF時は、RX読み取りが行われないこと。
