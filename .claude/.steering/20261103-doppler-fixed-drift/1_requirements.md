# 要求内容

## 概要

- v0.1.5 にて、Dopplerモードを「受信固定」にすると受信キャリアが徐々に低い周波数へ、「送信固定」にすると逆に高い周波数へドリフトする不具合を修正する。
- 受信固定／送信固定モードにおいて、固定していない側の周波数に「固定側のドップラー変化分」を反映し、固定側が一定であることを実際の電波上でも保証する。

## 背景

### 現象

| モード   | 症状                                                       |
| -------- | ---------------------------------------------------------- |
| 受信固定 | 受信キャリアが、徐々に低い周波数へドリフトする             |
| 送信固定 | 受信キャリアが、受信固定とは逆に、高い周波数へドリフトする |

### 原因（調査結果）

- 周期処理（`useTransceiverCtrl.ts` の `updateFreq` → `applyDopplerShiftCorrections`）は、固定していない側を「自分側の基準周波数 × 自分側のドップラー係数」のみで算出している。
  - Tx: `txBase × (1 − v/c)`
  - Rx: `rxBase × (1 + v/c)`
- これは衛星固定モード（衛星内の周波数を常に基準値に保つ）の計算式であり、受信固定／送信固定でもそのまま流用されている。
- 受信固定では「Txが下りのドップラー分（`Δf_down_trans`）を見越して余計にずれる」、送信固定では「Rxが上りのドップラー分（`Δf_up_trans`）を加味してずれる」必要があるが、現状はこの項が反映されていない。
- 固定側の値からSum（送受信基準周波数の和）を保って反対側の基準周波数を逆算する処理（`FrequencyTrackService.calcInvHeteroBaseFreqByRxFreq`）は、無線機からのRx通知（ダイヤル操作）時にしか呼ばれない。そのため通常の追尾中は基準周波数が静的なままとなり、パス中のドップラー係数の変化分だけ誤差が蓄積する。
- ドリフト量はそのパス中のドップラー変化分（数kHz規模）。向きは、受信固定では衛星が近づく状態から遠ざかる状態に移るにつれ受信キャリアが低い側へ、送信固定では逆向きとなる。
- v0.1.4f でも周期処理のフラグ構造は同一のため、v0.1.5 のダイヤル対応で混入したリグレッションではなく、既存の設計上の問題である。

### 各モードの仕様（正）

| モード   | 制御の目的                                                       | 地上局の送信周波数                                                       | 地上局の受信周波数                                                       |
| -------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------ | ------------------------------------------------------------------------ |
| 衛星固定 | 衛星内の周波数を常に基準値に保つ。送受信ともにフル補正する       | `f_up_nominal − Δf_up`                                                   | `f_down_nominal + Δf_down`                                               |
| 送信固定 | 送信周波数を動かさない。受信側だけでドップラーのズレを全て追う   | `f_up_nominal`（固定）                                                   | `f_down_nominal + Δf_up_trans + Δf_down`（上りのズレの影響も加味する）   |
| 受信固定 | 受信周波数を動かさない。送信側を余計に動かして下りのズレを相殺する | `f_up_nominal − Δf_up − Δf_down_trans`（下りのズレも見越してずらす）     | `f_down_nominal`（固定）                                                 |

- 上表は順ヘテロダイン（アップリンクが増えるとダウンリンクも増える）を基準とした記述。RSTは逆ヘテロダイン（Sum一定）を扱うため、実装時は符号が反転する点に注意する。
- 衛星固定モードは正しく動作しており、変更対象外。

## 要求仕様

### 要求A: 受信固定モードのTx算出の修正

1. Auto ON中の受信固定モードでは、Rxは固定値（選択中衛星の受信周波数）のまま、周期処理ごとに下りのドップラー係数の変化を反映して、Tx周波数を算出する（`Δf_down_trans` を見越す）。
2. これにより、衛星経由で戻ってくる自局の受信キャリアが、パス全体を通じて固定Rx周波数に対してドリフトしないこと。

### 要求B: 送信固定モードのRx算出の修正

1. Auto ON中の送信固定モードでは、Txは固定値（選択中衛星の送信周波数）のまま、周期処理ごとに上りのドップラー変化（`Δf_up_trans`）を反映して、Rx周波数を算出する。
2. これにより、送信周波数が固定でも、受信キャリアがパス全体を通じてドリフトしないこと。

### 要求C: 既存仕様との整合

1. 衛星固定モードの計算結果は変更しない。
2. 補正値（Tx/Rx周波数補正値）、ダイヤル操作による基準周波数の更新（Sum維持）、ダイヤル操作終了後の固定側再送信の既存仕様を維持する。
3. 「Tx周波数は無線機→RSTへ逆同期しない」仕様（20261010-207-tx-skip）を維持する。
4. 固定側の周波数は、Auto ON時の設定値のまま周期処理で更新しない。

## 確認事項（設計時に確認する）

1. 送信固定モードで必要となる、Tx固定値からRx基準値を逆算する計算（旧 `calcInvHeteroBaseFreqByTxFreq`。83e96f19 で削除済み）を復活させてよいか、別の式で表現するか。
2. 反対側の周波数算出を「毎周期、Sumを保って基準周波数を再導出する」方式とするか、「パス開始時の係数との差分のみを反映する」方式とするか。
3. 実機検証用に、受信固定と送信固定でそれぞれ1パス分の追尾ログ（`rst.log`）を取得し、修正前のドリフト量を確認できるか。

## スコープ外（Non-Goals）

- 衛星固定モードの計算式の変更。
- ダイヤル操作時の無線機→RST反映ロジック、およびRx読み取り待ちの仕組みの変更。
- 順ヘテロダイン／逆ヘテロダインの自動判別ロジックの追加（現行の逆ヘテロダイン前提を維持する）。
