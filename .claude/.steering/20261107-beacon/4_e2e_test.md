# E2Eテスト一覧：Beacon対応

要求は [`1_requirements.md`](./1_requirements.md)、設計は [`2_design.md`](./2_design.md) を参照。

## 1. 前提

### 1.1 実行環境と自動化の区分

- E2E（`src/__tests__/playwright/`）は、Playwright で Electron アプリを起動して画面を操作する。無線機は接続されない。
- Auto ON は無線機の接続（`ApiTransceiver.isReady`）が前提のため、無線機がない環境では Auto ON にできない。
- そのため、テストを次の3つに分ける。

| 区分 | 内容                                                   | 実施方法                                                                                   |
| ---- | ------------------------------------------------------ | ------------------------------------------------------------------------------------------ |
| A    | Auto OFF のまま確認できる画面操作                      | Playwright で自動化する（一部は手動）                                                      |
| B    | Auto ON が必要。周波数の送信内容までは見なくてよい     | 実機（IC-9700 など）で手動実施する。将来、無線機シミュレータを E2E に組み込めれば自動化する |
| C    | 無線機側の操作（ダイヤル）や、無線機の表示の確認が必要 | 実機で手動実施する                                                                         |

### 1.2 実施方法の表記（2章の「実施」列）

| 表記           | 意味                                                                                   |
| -------------- | -------------------------------------------------------------------------------------- |
| **自動**       | `npm run test:e2e` で自動実行される（対応する自動テストは 3.1 を参照）                 |
| 手動           | 無線機なしで確認できるが、自動化していない。アプリを起動して手動で確認する             |
| 手動（実機）   | 無線機（実機）を接続し、手動で確認する                                                 |

集計：

| 区分 | 件数 | 自動 | 手動 | 手動（実機） |
| ---- | ---- | ---- | ---- | ------------ |
| A    | 22   | 20   | 2    | 0            |
| B    | 26   | 0    | 0    | 26           |
| C    | 2    | 0    | 0    | 2            |
| 合計 | 50   | 20   | 2    | 28           |

### 1.3 テストデータ

`frequency.json` は外部から取得するため、ビーコン周波数の有無が安定しない。そのため、テスト用の衛星を次のように用意する。

| データ | 内容                                                                                                                            |
| ------ | ------------------------------------------------------------------------------------------------------------------------------- |
| 衛星B  | ビーコンあり、サテライトモード有効（例：アップリンク 145.970 MHz LSB / ダウンリンク 435.633 MHz USB / ビーコン 435.610 MHz CW） |
| 衛星N  | ビーコンなし、サテライトモード有効                                                                                              |
| 衛星S  | ビーコンあり、サテライトモード無効                                                                                              |

- 自動テストでは、fixture（`fixtures.ts`）で、起動前に一時ディレクトリへ設定ファイル（`app_config.json`）・既定衛星定義（`default_satellite.json`）・軌道要素（`omm.json`）を書き込み、そのディレクトリをアプリのユーザデータディレクトリとして起動する（3 参照）。
  - 衛星B/N/S は、ユーザ登録衛星（TLE を設定ファイルに持つ）として用意し、ネットワークから取得する軌道要素に依存しない。
  - アクティブ衛星の無線設定は既定衛星定義に存在する衛星だけ読み込まれるため、既定衛星定義にも追加する。
- 衛星B/N/S は、表示中の衛星グループに入れておく。
- 手動テストでは、衛星設定画面で衛星B/N/S に相当する衛星を用意する。

### 1.4 共通の確認方法

| 確認対象            | 確認方法                                                                                                            |
| ------------------- | ------------------------------------------------------------------------------------------------------------------- |
| Beaconボタンの状態  | `Beacon` ボタンの活性/非活性、ON/OFF の表示（`mode_btn_on` / `mode_btn_off`）                                       |
| 固定モード          | 固定モードのセレクトボックスの表示値と、活性/非活性                                                                 |
| Rx/Tx周波数         | 無線機制御パネルの Rx/Tx 周波数の表示値                                                                             |
| Rx/Tx運用モード     | Mode 欄の Rx/Tx 運用モードの表示値                                                                                  |
| 通知                | 画面のトースト表示                                                                                                  |
| 無線機（区分B/C）   | 無線機の表示（MAIN/SUB の周波数・モード）、RST のログ（`%APPDATA%/rst/logs/rst.log` の `Beacon ON` / `Beacon OFF`） |

## 3. 自動化の方針と結果

| 項目             | 内容                                                                                                                                                                                                        |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ファイル         | `src/__tests__/playwright/beacon.test.ts`、テストデータは `src/__tests__/playwright/helpers/beaconTestData.ts`（共通部分は `helpers/e2eTestData.ts`）                                                       |
| テストデータ     | `fixtures.ts` の `testData` オプション（`test.use` で指定）。E2E は常に、一時ディレクトリにテストデータを置き、環境変数 `RST_E2E_USER_DATA_DIR` でアプリのユーザデータディレクトリとして起動する。テスト後に一時ディレクトリを削除する |
| アプリ側の対応   | `src/main/util/E2eUserDataPath.ts` を追加し、`main.ts` の最初に読み込む。環境変数がある場合のみ `app.setPath("userData", ...)` で切り替える（通常の起動では何もしない）。ユーザデータディレクトリが分かれるため、起動中のRSTがあっても二重起動の判定に当たらない |
| 起動時の環境変数 | `ELECTRON_RUN_AS_NODE` が設定された環境（VS Code の拡張から起動したシェルなど）では Electron が起動しないため、fixture で取り除いて起動する                                                                 |
| 衛星設定の保存   | E-02/E-03 は、衛星設定画面の操作ではなく、preload の API（`getAppConfig` → `storeAppConfig` → `refreshAppConfig`）で保存後の通知を再現する                                                                 |
| 待ち合わせ       | ボタンの状態（ON表示）や選択値を `expect` / `expect.poll` で待つ（タイムアウト 10 秒）                                                                                                                      |
| セレクタ         | 無線機制御パネルに `data-testid` を追加（`beacon-btn`、`doppler-shift-mode`、`rx-frequency`、`tx-frequency`、`rx-frequency-adjustment`、`rx-ope-mode`、`tx-ope-mode`、`satellite-mode-btn`、`auto-btn`）    |
| 実行方法         | `npm run test:e2e`（ソースに変更があれば、実行前に自動でビルドする）。ファイル指定は `npx playwright test beacon`、テスト指定は `npx playwright test beacon -g "E-01"`                                       |

### 3.2 既存の E2E の移行

- 既存の fixture は、起動前後に electron-store の設定をクリアしていたが、テスト側（Node.js）の electron-store は `%APPDATA%/electron-store-nodejs/Config/` を指しており、アプリ本体の設定（`%APPDATA%/rst/`）はクリアされていなかった。
  - そのため、既存の `startup.test.ts`、`satellite.test.ts` はユーザの実データで起動していた。
  - 「衛星の追加」は、実データのグループへ衛星を追加・保存しうる状態だった（すでに登録済みの場合は「重複したデータは移動できません」が表示されていた）。
- 対応として、すべての E2E を一時ディレクトリで起動する形に統一し、electron-store のクリア処理は削除した（`testData` の既定値は、衛星なしの基本の設定）。
- `satellite.test.ts` は、テスト用の衛星3つを軌道要素（`omm.json`）として用意し、次を確認する形に書き直した。
  - 衛星の追加：空のグループに衛星を移動し、OKで保存されること（重複の通知が出ないこと）
  - 同じ衛星を追加した場合：重複の通知が表示され、追加されないこと
- `startup.test.ts` に「地図タイルの表示」を追加した（パッケージ化せずに起動した場合に地図タイルを参照できなかった問題の修正を確認する）。
